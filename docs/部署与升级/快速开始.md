# 快速开始（源码买家 / 首次部署）

面向拿到源码后要跑起来的人。**两条路**：Docker 一键演示（约 10 分钟），或本机裸跑（开发/二次开发）。

> 本文所有命令都经过真机实测，**每一步都附期望输出**——照抄即可，不确定时对照输出定位卡在哪一步。

## 一、Docker 一键演示（推荐先走这条）

### 步骤 0 · 前置检查（30 秒）

```bash
docker compose version
free -m | head -2
df -h / | tail -1
```

> 期望：能看到版本号（Docker 20.10+ / compose v2）
> 期望：可用内存 ≥ 4GB（低于 4GB 跑数据库+平台会 OOM）
> 期望：可用磁盘 ≥ 10GB

### 步骤 1 · 克隆代码（国内网络可能慢）

```bash
git clone https://github.com/qsumm/TestOPS.git && cd TestOPS
```

> GitHub 在国内网络不稳是常态（实测三种报错：`end of file` / 连接超时 / 5 分钟零字节）。
> 重试 2~3 次通常能过；持续不通用镜像加速（只代理只读 clone，密钥不经过它）：
> ```bash
> git clone https://gh-proxy.com/https://github.com/qsumm/TestOPS.git && cd TestOPS
> ```

### 步骤 2 · 填三个密钥（必须换）

```bash
cp backend/.env.example .env
python3 -c "import secrets;print(secrets.token_urlsafe(48))"
```

上面那条**跑三次**，把三个结果分别填进 `.env`（用编辑器打开改）：

| 变量 | 用途 | 不换的后果 |
|---|---|---|
| `JWT_SECRET` | 登录令牌签名密钥 | 任何人都能伪造登录令牌 |
| `KEY_STORE_SECRET` | LLM API Key 的落库加密密钥 | 你填的模型 Key 可被解密 |
| `DB_PASSWORD` | 数据库口令 | 本机试玩可留空；公网/多人使用必须填 |

**可选配置**（同样写在 `.env` 里，一行一个）：

| 变量 | 作用 |
|---|---|
| `ADMIN_PASSWORD=你的密码` | 覆盖管理员初始密码（默认 `admin123`；**公网部署强烈建议设置**） |
| `PLATFORM_PORT=8848` | 换对外端口（平台日志里打印的地址会跟着变；云上记得放行安全组） |
| `DB_HOST_PORT=2891` | 换数据库对外端口 |

### 步骤 3 · 构建并启动（首次约 2~4 分钟）

```bash
bash deploy/up.sh
```

`up.sh` 会构建 → 启动 → **自动等就绪** → 打印访问地址与管理员初始密码。

> 想手动分步：
> ```bash
> docker compose --env-file .env -f deploy/docker-compose.yaml up -d --build
> bash deploy/wait-ready.sh
> ```

三个**必须**注意的点（都是实测踩过的）：

| 要求 | 原因 |
|---|---|
| **必须带 `--env-file .env`** | `-f` 指向子目录时 compose 的项目目录变成 `deploy/`，根目录 `.env` 不会被自动读取 → 密钥/LLM 变量全为空 |
| **必须带 `--build`** | `up` 不会重建已存在的同名镜像 → 改了代码不重建，界面还是旧的 |
| **构建卡住别硬等** | 慢镜像源上首次可能十几分钟（pip 下依赖）。三档加速见 [自建部署加速指引](自建部署加速指引.md)：换源 / 离线 wheel（25 秒） / 预构建镜像 |

### 步骤 4 · 等平台就绪（别跳过这步）

平台的启动顺序是「数据库就绪 → 迁移 → 起 HTTP 服务」，**首次启动要 30~90 秒**。
这期间你会看到这两种**正常现象**，不是故障：

| 你看到的 | 真实原因 |
|---|---|
| `curl: (56) Recv failure: Connection reset by peer` | 端口映射已建立，但 uvicorn 还没监听（容器在等数据库） |
| `docker logs aiops-platform \| grep 管理员` 没有输出 | 平台还没启动完，管理员种子尚未执行 |
| `docker ps` 里 `aiops-seekdb` 显示 `Restarting` | SeekDB 首次初始化要几十秒，容器进进出出属正常 |

用脚本等（最多 5 分钟，就绪后打印地址/初始密码/容器状态）：

```bash
bash deploy/wait-ready.sh
```

慢机器放宽：`WAIT_TIMEOUT=600 bash deploy/wait-ready.sh`。
（用了 `up.sh` 的话，这一步它已经自动做完了。）

### 步骤 5 · 验证是否成功（4 条命令）

```bash
curl http://127.0.0.1:8848/api/health
docker ps --format "{{.Names}} | {{.Status}}"
docker logs aiops-platform | grep -i "管理员"
python3 tools/smoke_mainflow.py --base http://127.0.0.1:8848 --no-llm
```

**① 健康检查** —— 期望：
`{"code":0,"msg":"ok","data":{"app":"aiops-platform","status":"up","version":"1.9.0",...}}`

**② 四个容器** —— 期望都 Up / healthy：
`aiops-platform` / `aiops-seekdb` / `aiops-agent-1` / `aiops-agent-2`

**③ 管理员账号 + 初始密码 + 访问地址**（首次启动才有）—— 期望三行：

```text
已创建管理员账号 admin，初始密码 = xxxxxxxxxxxx（请立即登录修改；需要固定密码可在 .env 里设 ADMIN_PASSWORD）
已创建只读演示账号 demo/demo（仅用于体验，无处置权限）
平台就绪 → http://127.0.0.1:8848（管理员 admin，初始密码见上方启动日志）
```

**④ 冒烟测试** —— 5 段 29 项（写操作幂等自清理，只用标准库），期望**退出码 0**。

### 步骤 6 · 首次登录并改口令

浏览器打开 `http://127.0.0.1:8848`（云服务器换成服务器 IP，安全组放行 `PLATFORM_PORT`），
用 **admin + 步骤 5③ 的初始密码** 登录，**首登先改口令**。
只读体验可用 `demo / demo`（无处置权限）。

### 步骤 7 · 让两台模拟主机接入（Agent 注册强制一次性令牌）

1. 平台里「主机管理 → 接入新主机」→ **生成两枚**安装令牌（令牌一次性，两台各一枚）
2. 两枚令牌写进 `.env`：
   ```bash
   echo 'AIOPS_INSTALL_TOKEN_1=<第1枚>' >> .env
   echo 'AIOPS_INSTALL_TOKEN_2=<第2枚>' >> .env
   ```

> mock-web-01 用
> mock-db-01 用
3. 重建 agent 容器（**不用 `--build`**）：
   ```bash
   docker compose --env-file .env -f deploy/docker-compose.yaml up -d
   ```
4. 回到「主机管理」，两台模拟主机应显示**在线**并每 15s 上报

### 步骤 8 · 想立刻看到它干活

```bash
docker compose --env-file .env -f deploy/docker-compose.yaml exec platform \
    python scripts/seed_demo.py --days 7

bash deploy/faults/cpu_spike.sh
```

> 灌 7 天演示数据（指标 + 规则 + 历史事件 + 案例卡）
> 触发一次真实故障（5 种：探活失败 / CPU / 磁盘 / 内存 / 进程假死，各一条命令，自动恢复）

跑通后可在平台内置「文档 → 使用手册 → 平台演示视频」看一遍全链路演示。

## 二、本机裸跑（开发用）

```bash
uv venv --python 3.11
uv pip install -r backend/requirements.txt

cp backend/.env.example backend/.env

cd backend
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8848 --reload

curl -fsSL http://<平台地址>/preflight_linux.sh | bash -s -- --server http://<平台地址>
bash agent/install.sh --server http://<平台地址> --token <设置页生成的安装令牌>
```

> 依赖：Python 3.11（uv 管理）+ 一个 MySQL 协议数据库（SeekDB v1.4.0 或 MySQL 8）
> 配置（backend/.env，已 gitignore）
> 填 DB_* 与安全密钥
> 建表（索引手写，见 04 §7）
> 接一台真机（Agent）
> ① 先自检（只读）
> ② 自检通过后安装

**注意**：迁移必须从 `backend/` 目录执行（`alembic.ini` 与 `.env` 都按该目录解析）。

> 裸跑时管理员初始密码同样是 `admin123`（或 `.env` 里 `ADMIN_PASSWORD` 指定的值），打印在 uvicorn 启动日志里（`grep 管理员`）。

## 三、第一次进来做什么

| 步骤 | 位置 | 说明 |
|---|---|---|
| 改密码 | 右上角账号 → 修改口令 | 初始密码只在首次启动日志里出现一次 |
| 配 LLM | 系统设置 → LLM 配置 → 新增 | 填 Base URL / API Key / 主模型 / 快模型 / Embedding 模型；点「测试」验证连通 |
| 配通知 | 系统设置 → 通知渠道 | 飞书/钉钉粘 webhook 即可；邮件填 SMTP 串；也可填 apprise_url 接其余 150+ 渠道 |
| 激活 License | 系统设置 → License | 离线 HMAC 串，绑定机器指纹（换机需重新签发） |
| 接主机 | 主机管理 → 接入新主机 | 复制一键安装命令到目标机执行（先跑 preflight 自检） |
| 建规则 | 告警规则 → 新建规则 | 指标/探活/服务/Prometheus 四种作用域；先点「测试运行」看命中情况 |
| 容量预测 | 告警规则 → 算法选「容量趋势预测」 | 表达式 `>90@7d` = 预计 7 天内到 90% 就提前告警（需 ≥3 天历史） |

## 四、常见问题

**Q：构建卡在 pip 下载 / 十几分钟不动？**
A：慢镜像源。换源或用离线 wheel（见 [自建部署加速指引](自建部署加速指引.md)）。
判断是"卡"还是"在下载"：`grep -E "Collecting|Downloading" 构建日志 | tail`。

**Q：刚 `up -d` 完就 curl 报 `Connection reset by peer`？**
A：正常——平台要先等数据库就绪再起 HTTP 服务，首次 30~90 秒。用步骤 4 的等待命令，
或看 `docker logs aiops-platform | grep -E "平台就绪|管理员"` 确认。

**Q：数据库容器一直 `Restarting`，平台刷「等待数据库…」，curl 报 `Connection reset by peer`？**

A：数据库起不来，**通常是磁盘或内存不足**——SeekDB 对资源不足**不报错、直接退出**
（`Exit=1`、`OOMKilled=false`，日志停在 `server_start 3/14`，容器反复重启，平台等不到库）。
按官方最低要求逐项核对：

| 项 | 要求 | 怎么查 |
|---|---|---|
| 数据盘空闲 | **> 15GB**（最常踩） | `df -h /` |
| 可用内存 | **≥ 2GB** | `free -m` 看 available |
| CPU | ≥ 1 核 | `nproc` |

加 swap、放大 `shm_size`、`--privileged` 都**不能**替代（实测无效）。
解决：清磁盘 / 停同机其它数据库服务 / 换机器。**不是部署步骤错了。**

**Q：`docker logs aiops-platform | grep 管理员` 什么都没输出？**
A：说明管理员已存在（**只在首次创建时打印**）。用平台里已有账号登录即可；
想重新拿初始密码：删掉数据卷重建（`down -v`，**数据不可恢复**），或事先在 `.env` 设 `ADMIN_PASSWORD`。

**Q：AI 功能报 `LLM_UNAVAILABLE`？**
A：系统设置里没配模型，或 Base URL/Key 不对。采集、告警、静默、通知、巡检**都不依赖 LLM**，只有诊断/摘要/案例向量需要。
容器部署时还有一种常见原因：compose 命令没带 `--env-file .env` → `LLM_*` 变量为空。
可用 `docker exec aiops-platform env | grep LLM_` 自查。

**Q：指标图只有最近 2 小时？**
A：设计如此——明细只留在内存环形缓冲（默认 2h），更早的走 1m 聚合表 `metric_agg`。看更长时间窗时查询会自动落到聚合表（返回 `source=metric_agg`）。

**Q：embedding 用不了？**
A：案例召回会自动降级为文本匹配（`mode=text`），诊断流程不受影响。注意部分厂商的 `/v1/embeddings` **不是 OpenAI 形状**（请求 `texts` 而非 `input`），网关已适配两种形状（见 04 §10）。

**Q：容器重建后平台里多出一台"新主机"？**
A：容器重建会换掉网卡 MAC / machine-id，机器指纹随之变化。给 Agent 设 `AIOPS_FINGERPRINT=<固定串>`
（compose 里模拟主机已这么做）即可在容器/不可变基础设施下保持身份稳定。

**Q：在容器里做故障演示，磁盘打满没触发告警？**
A：容器内 `psutil` 读的是**整机**磁盘（Docker Desktop 上是几百 G 稀疏盘），百分比很难冲到阈值。
磁盘场景请在真实机器上演示，或调低规则阈值；CPU/内存脚本已默认按 `nproc`/85% 加大强度。

**Q：目标机装 Agent 报 `'type' object is not subscriptable`？**
A：目标机 Python 太旧（Agent 需要 **3.9+**）。脚本会自动挑选 `python3.11/3.12/3.10/3.9`，
都没有时会提示安装方式（RHEL 系 `dnf install -y python3.11 python3.11-pip`）。也可显式指定：
`PYTHON=/usr/bin/python3.11 bash install.sh --server ...`。

**Q：目标机装 Agent 卡在 `pip install psutil httpx`（Errno 101）？**
A：目标机没有到公网 PyPI 的出网（内网常态）。**不用管**：安装脚本会自动探测国内镜像，
全断时改从平台内置依赖包（`{平台}/wheels/`）拉——只要平台可达就装得上。

**Q：`curl http://<平台>/install.sh` 返回 404？**
A：这是修复过的老问题（安装件此前没被分发）。现在平台会直接提供 `/install.sh` 与 `/agent_main.py`，
且这两个路径**不受 License 门禁影响**——否则锁定实例就没法接入主机了。

**Q：迁移报 `VARCHAR requires a length` 或 autogenerate 崩？**
A：SeekDB 的反射有两处坑（`BLOCK_SIZE` 语法、`VECTOR` 列），我们已在 `migrations/env.py` 里关掉索引/唯一约束比对并跳过 `case_cards` 反射。**新增索引请手写**（见 04 §7/§10）。

**Q：告警不落库/不通知？**
A：按顺序查：① 规则是否启用且未停用；② 是否被静默策略命中（`mute_type=0` 事件不产生）；③ 通知渠道是否启用并通过「测试」；④ 通知节奏三参数（只发一次/重发步长/封顶）是否已到限制。

## 五、二次开发须知

开工前务必读仓库根目录 **`AGENTS.md`**：需求唯一基准、技术栈锁死、六条强制规则、任务类型必读表。
架构级选型必须落 ADR（`docs/01-需求与设计/decisions/`）。
改前端后请跑 `pytest backend/tests -q`——其中 `test_d3_frontend_assets.py` 会做模块语法门禁
（少一个括号就会让整页空白，且浏览器不报错，我们在 D3 踩过）。
