# 自建部署加速指引（构建卡住 / 十几分钟？）

> 适用：从开源仓库**自己构建**镜像的用户。2026-11 实测：某用户在慢镜像源上
> `docker compose build` 卡住 16 分钟（`Building 993.7s`），根因是镜像构建时要下
> numpy+scipy+scikit-learn ≈ 90MB。本文档给出三档解法，按代价从低到高排。

---

## 0. 先看结论

| 你的情况 | 用哪一档 | 预期耗时 |
|---|---|---|
| 能拉 Docker Hub 镜像 | **档一：预构建镜像** | 分钟级，零构建 |
| 构建过一次、只是改代码重建 | **档二：BuildKit 缓存** | **秒级**（已内置，不用配置） |
| 内网 / 镜像源很慢 / 要完全离线 | **档三：离线 wheel** | 秒级（一次性准备） |

改完之后，**默认构建已经比原来快很多**（重依赖 90MB 已移出主依赖），
下面三档是进一步提速。

---

## 档一：直接用预构建镜像（最省事）

不想本地构建就把 compose 里 `platform.build` 段注释掉，改用镜像：

```yaml
  platform:
    image: ghcr.io/qsumm/testops-platform:v1.9.0
```

> 其余配置（environment / volumes / ports）照旧

> compose 里 `build` 与 `image` 同时存在时仍会本地构建，**必须删掉 build 段**。

---

## 档二：BuildKit pip 缓存（已内置，无需配置）

Dockerfile 已改用 BuildKit 缓存层：

```dockerfile
RUN --mount=type=cache,target=/root/.cache/pip pip install ...
```

效果：**第一次构建仍受镜像源带宽限制，之后每次重建都是秒级**（pip 的下载缓存跨构建复用）。

> 注意：老版本 Docker（<23）可能未启用 BuildKit；确认：
> `docker buildx version` 有输出即可；没有的话设 `export DOCKER_BUILDKIT=1`。

---

## 档三：离线 wheel（内网 / 慢源 / 完全断网）

在一台**网络好**的机器上一次性把 wheel 下好：

```bash
bash tools/build_platform_wheels.sh
WITH_AI_DEPS=1 bash tools/build_platform_wheels.sh
```

> 产物在 deploy/wheels/
> 想连「孤立森林」算法一起带上：

把整个仓库（含 `deploy/wheels/`）拷到目标机后构建——Dockerfile 检测到该目录非空就会
**全程不联网**（`pip install --no-index --find-links /opt/wheels`），构建只剩拷贝层：

```bash
docker compose -f deploy/docker-compose.yaml build platform
```

> `deploy/wheels/` 内容**不入 git**（几十 MB 二进制），但目录本身保留（`.gitkeep`）——
> 目录缺失会让 `COPY deploy/wheels/ /opt/wheels/` 直接失败。

---

## 附：换更快的 pip 镜像源

不同镜像源带宽差别很大（实测同一时刻差异可达 10 倍）：

```bash
docker compose -f deploy/docker-compose.yaml build \
  --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple platform

echo 'PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple' >> .env
```

> 构建时指定（不写进文件）
> 或写进 .env（compose 已读取）

常见国内源：`mirrors.aliyun.com/pypi/simple`（默认）、`pypi.tuna.tsinghua.edu.cn/simple`、
`mirrors.ustc.edu.cn/pypi/simple`、`mirrors.cloud.tencent.com/pypi/simple`。

**Docker 镜像拉不动时**（默认走 daocloud，但其后端在 Cloudflare，部分机房不通）：
可换华为云镜像加速（真机实测可用）：

```
swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/library/python:3.11-slim
swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/oceanbase/seekdb:latest
```

把 Dockerfile 的 `FROM` 与 compose 的 `image:` 换成上面的地址即可（或把镜像
`docker tag` 成这两个名字后构建）。

> 换源只影响**构建期**；运行时平台不连 PyPI。

---

## 附：为什么把 scikit-learn 移出主依赖

`requirements.txt` 原本硬依赖 `scikit-learn==1.9.1`，它会带进 `numpy`(16.9MB) +
`scipy`(35.3MB) + `sklearn` —— 在 91 kB/s 的源上就是**十几分钟**。

现在：

- 主依赖 `requirements.txt`：不含 numpy/scipy/sklearn（构建体积与时间大幅下降）
- 可选增强 `requirements-ai.txt`：需要「孤立森林」算法时再装
  （`INSTALL_AI_DEPS=true docker compose ... build platform`）
- **不装也不影响核心能力**：
  - 孤立森林算法自动降级为 3σ（页面标注"降级"）
  - 磁盘容量趋势预测（D234）已改为**纯 Python 最小二乘**（含星期哑变量），
    与 sklearn 结果等价（单测比对误差 < 1e-6），不依赖 numpy

## 排障：构建卡住时先看这几行

```bash
docker compose -f deploy/docker-compose.yaml build platform 2>&1 | tee /tmp/build.log
grep -E "Collecting|Downloading|使用镜像源|跳过可选" /tmp/build.log | tail -20

df -h / ; free -m

docker compose -f deploy/docker-compose.yaml build \
  --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple platform

```

> 1) 卡在哪一步？BuildKit 的每层都有编号（#7 [platform 3/9] …）
> 2) 确认是不是在下载（而不是真卡死）：看网络与磁盘
> 3) 换源重来（缓存层会保留已下好的包）
> 4) 彻底断网 → 档三离线 wheel
